# ПАРТА — учебная платформа для MAX

ПАРТА — учебный контур для школ и колледжей: преподаватели выдают задания,
ученики работают с канбан-доской, сдают решения и получают XP, а проверка и
взаимопроверка встроены в общий процесс. Интерфейс адаптирован под MAX и
обычный браузер, поддерживает светлую и тёмную темы.

Проект состоит из Go-бэкенда, React/Vite-фронтенда и SQLite. Docker-образ
собирает обе части и запускает единый сервер, который отдаёт API и статику на
порту `8080`.

## Требования и зависимости

Для запуска нужен только Docker. Полный список зафиксированных версий Go,
Node.js, Alpine и пакетов проекта — в [requirements.txt](requirements.txt).

## Сборка и запуск контейнера

```bash
docker build -t parta .
```

```bash
docker run -d -p 8080:8080 -e MAX_BOT_TOKEN="your_bot_token_here" parta
```

Go-часть сборки полностью автономна: зависимости лежат в `backend/vendor`, а
Dockerfile собирает бинарник с `-mod=vendor` без `go mod download`.

После первого запуска база создаётся автоматически и заполняется тремя
демо-аккаунтами. Сервис доступен по адресу http://localhost:8080.

## Демо-доступ

В браузере доступны ровно три аккаунта:

| Роль | Аккаунт | Код |
| --- | --- | --- |
| Студент | `max:000000001` | не требуется |
| Преподаватель | `max:000000002` | `TEACHER2026` |
| Администратор | `max:000000003` | `ADMIN2026` |

Коды можно переопределить переменными `TEACHER_INVITE_CODE` и
`ADMIN_INVITE_CODE`.

## Вход через MAX

При открытии из MAX приложение проверяет подпись запуска по `MAX_BOT_TOKEN`.
При первом входе показывается выбор роли; после создания аккаунта вход
происходит автоматически по `max:<max_user_id>`.

Если `MAX_BOT_TOKEN` не задан, MAX-авторизация вернёт `401`, но браузерный
демо-доступ продолжит работать.

Если окружение не доверяет российским корневым сертификатам, для MAX Bot API
можно включить `MAX_BOT_INSECURE_SKIP_VERIFY=true`. Используйте это только
как временный обходной путь.

## Реалтайм и reverse-proxy

События доставляются двумя транспортами с одного и того же хаба:

- **WebSocket** `GET /ws?token=<jwt>` — основной канал;
- **long-poll** `GET /api/events/poll?after=<cursor>&timeout=20` — фолбэк.

Фронтенд сам переключается на long-poll, если WebSocket не открылся за 10
секунд (типичный признак прокси без проброса `Upgrade`). Long-poll — это
обычный завершённый HTTP-ответ, поэтому он проходит через любой буферизующий
reverse-proxy; WebSocket — нет.

Для нормальной работы WebSocket прокси перед приложением должен быть настроен
явно (см. [deploy/nginx-parta.conf](deploy/nginx-parta.conf)):

```nginx
location /ws {
    proxy_pass http://127.0.0.1:8080;
    proxy_http_version 1.1;
    proxy_set_header Upgrade    $http_upgrade;
    proxy_set_header Connection $connection_upgrade;
    proxy_buffering off;
    proxy_read_timeout 3600s;
}
```

Если правка прокси недоступна, приложение продолжает работать на long-poll:
индикатор в интерфейсе остаётся зелёным, задержка доставки — доли секунды.
