# Админка — `frontend/src/admin`

Модуль роли `admin`: люди, потоки и контроль выдач. Задания создаёт только
преподаватель (`frontend/src/teacher`), поэтому здесь они read-only.
Каркас — общий `AppShell` (`max-w-md`, тёмный фон, выход в шапке), визуальные
правила — `DESIGN_SPEC.md`, UI-кит — тот же, что в кабинете преподавателя.

Тема: тёмная по умолчанию и светлая по переключателю в шапке. Цвета — семантические
токены (`page`, `card`, `ink*`, `brand*`, `ok/warn/bad/team`) поверх CSS-переменных
в `src/index.css`; палитровые классы и hex в экранах не используются.

## Разделы

| Раздел | Файл | Что делает |
|---|---|---|
| Состояние контура | `components/AdminOverview.tsx` | KPI по людям, потокам, заданиям и очереди, активность сдач, ближайшие дедлайны, роли |
| Люди | `components/UsersPanel.tsx` | поиск и фильтры по роли/группе, создание, удаление, смена группы студента |
| Группы | `components/GroupsPanel.tsx` | создание и удаление потоков, состав с переводом и снятием с группы, список «без группы» |
| Задания и пары | `components/AssignmentsPanel.tsx` | назначения «группа + дисциплина + преподаватель» и все задания с прогрессом колонок |

Корень — `AdminApp.tsx`: hash-роутинг (`#/overview`, `#/users`, `#/groups`,
`#/assignments`), нижняя навигация, тосты, перезагрузка по WS-событиям сдач.

## Данные и интеграция

- `api.ts` реэкспортирует `fetchUsers` / `createUser` / `deleteUser`,
  `fetchGroups` / `createGroup` / `deleteGroup`, `fetchAssignments`, `fetchTasks`,
  `fetchSubmissions`, `fetchPeerReviews` и добавляет `updateUserGroup`.
- `updateUserGroup(id, groupId)` — `PATCH /api/users/{id}` с телом `{group_id}`.
  `null` убирает студента из группы, число переводит в другую. После мутации
  обновляется локальный список из ответа сервера.
- Роль задаётся только при создании: `POST /api/users`
  `{external_id, display_name, role, group_id}`. Смена роли существующего
  пользователя API не поддерживает — интерфейс об этом предупреждает.
- Студент создаётся обязательно с группой (backend отвечает `400`, если группы
  нет): форма подставляет первый поток и блокирует «Создать», пока групп нет.
- Кнопка удаления заблокирована для себя и для студентов с карточками работ
  (backend отвечает `422 guard_failed`): история сдач не удаляется. Ошибки
  `422` объясняются в тосте, а не показываются сырым кодом.
- Назначения и типы заданий read-only: их создаёт преподаватель через
  `POST /api/tasks`.
